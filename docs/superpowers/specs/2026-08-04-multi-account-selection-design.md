# 多运营商多账户选择设计

## 背景与目标

当前技能以单个运营商会话为中心。用户未来可能同时绑定联通、移动、电信、广电等运营商，并在同一运营商下绑定多张主卡。技能需要在不增加日常查询负担的前提下，准确判断用户想查询的账户或成员卡。

本次改造的目标是：首次绑定时建立易懂的中文别名和默认关系；日常查询优先自动选择；只有存在真实歧义时才展示脱敏候选项；始终避免泄露完整手机号和登录凭证。

## 方案选择

采用“本地账户注册表 + 独立会话文件”方案。

- 账户注册表只保存账户 ID、中文别名、运营商、脱敏号码、会话文件位置和默认关系。
- Cookie、Token 等敏感登录信息继续保存在独立会话文件中，文件权限限制为仅当前用户可读写。
- 不引入数据库，保持技能安装和维护简单。
- 不把敏感凭证与普通账户配置混合，便于后续增加运营商实现。

## 账户模型

每张需要独立登录的主卡对应一个账户，包含：

- 稳定账户 ID，例如 `unicom-work`；
- 用户设置的唯一中文别名，例如“工作联通”；
- 运营商标识，例如 `china_unicom`；
- 脱敏主号码，例如 `138****1234`；
- 对应的会话文件路径。

注册表维护两层默认关系：

- 全局默认账户：处理“查流量”等未指定运营商的请求；
- 运营商默认账户：处理“查联通流量”等只指定运营商的请求。

同一时间最多存在一个全局默认账户，每个运营商最多存在一个运营商默认账户。

## 账户选择规则

查询账户按以下优先级确定：

1. 用户在当前请求中明确指定账户 ID、准确别名或准确脱敏号码；
2. 当前对话中已经选定且仍符合本次条件的账户；
3. 用户指定运营商时，使用该运营商默认账户；
4. 用户未指定运营商时，使用全局默认账户；
5. 符合条件的账户只有一个时，直接使用；
6. 仍存在多个候选账户时，返回编号、中文别名、运营商和脱敏号码供用户选择，不做模糊猜测。

CLI 负责稳定、可测试的账户解析；Skill 负责识别自然语言中的运营商、别名和对话上下文，并把明确的账户传给 CLI。对话上下文不写入长期配置。

示例：

- “查工作联通的流量”选择别名为“工作联通”的账户；
- “再看看套餐”沿用当前对话已选账户；
- “查联通流量”选择联通默认账户；
- “查流量”选择全局默认账户；
- 没有默认且存在多个候选账户时，展示脱敏选项。

## 首次绑定流程

扫码登录成功后，系统读取运营商和脱敏主号码，并要求用户设置中文别名。交互模式提供“我的联通”等建议值，非交互模式允许通过参数直接指定。

- 第一张卡自动成为对应运营商默认账户；
- 第一张卡默认建议设为全局默认，用户可以拒绝；
- 同一运营商已有默认账户时，询问是否替换；
- 已有全局默认账户时，询问是否替换，不静默变更；
- 中文别名必须唯一，重复时拒绝保存并给出修改提示。

非交互式示例：

```bash
carrier-usage login --provider china_unicom --alias "工作联通" --default
```

计划提供以下账户管理命令：

```bash
carrier-usage accounts list
carrier-usage accounts rename <账户> "新别名"
carrier-usage accounts set-default <账户>
carrier-usage accounts set-provider-default <账户>
carrier-usage accounts remove <账户>
```

删除账户默认只解除注册。删除对应本地会话凭证必须由用户明确确认或传入专用参数，避免误删。

## 成员卡与副卡

成员卡和副卡不作为独立登录账户，而是从属于一个主账户。查询定位分为“主账户 → 成员”两级。

- 默认查询继续返回主账户下所有成员或副卡用量；
- 用户明确指定成员时，仅返回该成员；
- 全部候选中成员名称唯一时可以直接选择；
- 多个主账户下出现同名成员时，展示所属主账户、成员角色和脱敏号码供选择；
- 后续请求可在当前对话中延续已选主账户和成员。

成员匹配只使用运营商提供的显示名称、角色、脱敏号码或稳定标识，不用完整手机号建立索引。当前运营商未提供稳定成员标识时，不跨登录周期推断成员身份。

## 本地存储

默认存储布局：

```text
~/.config/carrier-usage/accounts.json
~/.local/share/carrier-usage/sessions/<account-id>.json
```

注册表结构示例：

```json
{
  "global_default": "unicom-work",
  "provider_defaults": {
    "china_unicom": "unicom-work"
  },
  "accounts": [
    {
      "id": "unicom-work",
      "alias": "工作联通",
      "provider": "china_unicom",
      "masked_phone": "138****1234",
      "session_path": "~/.local/share/carrier-usage/sessions/unicom-work.json"
    }
  ]
}
```

注册表和会话文件均采用安全文件权限。日志、错误消息、结构化输出和交互选项不得包含完整手机号、Cookie、Token 或原始请求头。

## 旧版本迁移

如果注册表尚不存在，但发现旧版单账户会话文件，首次使用时自动导入：

- 别名设为“我的联通”；
- 设为联通默认账户和全局默认账户；
- 新注册表引用或安全迁移现有会话；
- 在新账户成功查询前不删除旧文件；
- 迁移过程幂等，多次执行不会创建重复账户。

## 异常与边界处理

- 会话失效：指出失效账户的中文别名和脱敏号码，引导重新扫码登录该账户。
- 别名重复：拒绝保存，不自动追加不可预测的后缀。
- 删除默认账户：清除相关默认关系；若该运营商只剩一个账户，可将其补为运营商默认，但不擅自修改全局默认。
- 注册表损坏：保留原文件，不覆盖，并明确报告文件位置和恢复方法。
- 别名与账户 ID 同时匹配不同账户：视为歧义并要求明确选择。
- 刷新限流：以账户 ID 和运营商共同作为隔离键，避免同运营商的不同号码互相影响。
- 对话上下文失效或候选账户已删除：重新执行正常选择流程。

## 测试与验收

自动化测试至少覆盖：

- 首张卡、同运营商第二张卡及跨运营商绑定；
- 全局默认和运营商默认的建立、替换、清除与选择优先级；
- 明确账户、对话延续、唯一候选和多候选歧义；
- 主卡、成员卡、副卡的两级定位；
- 旧版单账户会话迁移及迁移幂等性；
- 会话过期、别名重复、删除默认账户和注册表损坏；
- 账户级刷新限流隔离；
- CLI 交互式与非交互式流程；
- 输出脱敏及敏感字段防泄漏；
- 中文触发词和多账户使用文档。

验收标准是：单账户用户升级后无需重新配置即可继续查询；存在明确默认关系时日常查询不增加追问；只有选择结果不唯一时才展示脱敏选项；新增运营商不需要修改账户选择核心逻辑。

## 本次范围

本次实现账户注册表、双层默认、账户管理命令、查询账户选择、旧会话迁移、成员选择规则以及相应中文 Skill 文档。不会实现新的移动、电信或广电业务接口，也不会持久化跨会话的自然语言上下文。
