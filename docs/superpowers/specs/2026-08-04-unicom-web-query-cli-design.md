# 中国联通网页查询 CLI 能力设计

## 背景与目标

当前 Skill 已能通过中国联通官方网页扫码会话查询账户概览、套餐余量、主副卡用量和联通云盘，但网页端仍有多项常用查询能力尚未封装。余额缺失问题已经证明：联通将不同业务拆分在独立页面和接口中，不能只依赖现有汇总与余量接口。

本次改造将联通网页的只读查询能力封装为稳定 CLI，供 Agent 使用结构化参数调用，而不是让 Agent 直接理解网页、接口字段或登录凭证。

首批目标业务包括：

- 剩余话费；
- 我的账单；
- 交费记录；
- 电子发票；
- 余量查询；
- 详单查询；
- 金融合约账单；
- 返费与赠款。

## 安全边界

所有能力保持只读。

- 不发起缴费；
- 不申请、重开、下载或发送发票；
- 不修改发票抬头、邮箱或联系方式；
- 不修改套餐、合约或账户信息；
- 不绕过短信验证、设备验证、二次认证、风控或实名认证；
- 不保存用户真实接口响应、Cookie、Token、完整请求头或完整号码；
- 遇到需要用户操作的认证步骤时，要求用户在联通官方 Chrome 页面完成。

## 方案选择

采用显式业务子命令方案，而不是继续扩展单个 `query --scope` 或暴露通用接口调用器。

显式子命令能为不同业务提供清晰的月份、时间范围、分类和分页参数，也能让 Agent 稳定发现和调用能力。联通接口地址和私有字段全部封装在 Provider 内部，不进入 Agent 提示词。

## CLI 结构

保留现有综合查询：

```bash
carrier-usage query --account "我的联通" --scope overview
```

新增只读业务命令：

```bash
carrier-usage balance --account "我的联通"
carrier-usage bills --account "我的联通" --month 2026-08
carrier-usage payments --account "我的联通" --from 2026-01 --to 2026-08
carrier-usage invoices --account "我的联通" --month 2026-07
carrier-usage allowances --account "我的联通" --detail
carrier-usage usage-details --account "我的联通" --category data --month 2026-08
carrier-usage contract-bills --account "我的联通"
carrier-usage rebates --account "我的联通"
```

所有命令统一支持：

- `--account`：账户 ID、准确中文别名或准确脱敏号码；
- `--format`：`summary` 或 `json`，默认为中文摘要；
- 复用全局默认、运营商默认、唯一候选和脱敏歧义选择规则。

时间型查询按业务增加：

- `--month YYYY-MM`；
- `--from YYYY-MM`；
- `--to YYYY-MM`。

具有分页的接口由 CLI 在合理范围内自动分页，并设置最大页数和记录数，防止无限请求。超出范围时返回明确的截断警告。

业务与命令映射：

| 联通网页能力 | CLI 命令 |
|---|---|
| 剩余话费 | `balance` |
| 我的账单 | `bills` |
| 交费记录 | `payments` |
| 电子发票 | `invoices` |
| 余量查询 | `allowances` |
| 详单查询 | `usage-details` |
| 金融合约账单 | `contract-bills` |
| 返费与赠款 | `rebates` |

## 组件与职责

新增独立的联通网页业务客户端，避免继续扩大现有 Provider：

```text
ChinaUnicomWebClient
├── query_balance()
├── query_bills(month)
├── query_payments(date_range)
├── query_invoices(month)
├── query_allowances()
├── query_usage_details(category, month)
├── query_contract_bills()
└── query_rebates()
```

每项能力分为三层：

1. 网页接口适配器：处理请求地址、方法、参数、Referer、超时和联通状态码；
2. 解析器：把联通易变化字段转换成运营商无关的不可变模型；
3. CLI 渲染器：输出稳定 JSON 或中文摘要。

现有账户注册表和扫码会话加载逻辑保持唯一入口。业务客户端只接收已认证的 HTTP 客户端，不自行读取其他浏览器资料，不暴露 Cookie。

## 统一返回结构

所有业务 JSON 使用统一外层结构：

```json
{
  "schema_version": "1.0",
  "provider": "china_unicom",
  "account_id": "china-unicom-ab12cd34",
  "account_alias": "我的联通",
  "query_type": "balance",
  "queried_at": "2026-08-04T16:19:41+08:00",
  "data": {},
  "warnings": []
}
```

金额统一使用十进制字符串，时间使用带时区 ISO 8601，月份使用 `YYYY-MM`。列表型业务返回 `items` 和查询范围；分页被截断时在 `warnings` 中说明。

余额示例：

```json
{
  "remaining_balance_cny": "142.35",
  "carried_balance_cny": "157.35",
  "deposited_this_month_cny": "30.00",
  "consumed_this_month_cny": "59.00"
}
```

账单模型至少包含月份、应付金额、实付金额、优惠金额、欠费金额和状态。交费记录至少包含时间、金额、渠道、方式和状态。发票模型只包含脱敏发票号码、金额、日期、类型和状态。

余量继续使用现有流量、语音、短信统一模型。详单按 `data`、`voice`、`sms` 分类，输出最小必要字段，不在默认摘要中展示敏感明细。

## 隐私与脱敏

- 手机号、对方号码、宽带账号和发票号码必须脱敏；
- 详单中的通话对象、短信对象、上网位置等默认最小化；
- 不打印或持久化原始运营商响应；
- 不打印 Cookie、Token、完整请求头、完整手机号或认证参数；
- 真实用户数据不进入测试 fixture、Git、Issue 或发布包；
- JSON 错误仅包含稳定错误码和中文说明；
- Agent 不得要求用户把验证码、会话文件或浏览器 Cookie 粘贴到对话中。

## Chrome 接口发现流程

接口发现使用用户已登录的 Google Chrome 会话，仅操作中国联通官方域名。

对每项业务：

1. 打开对应联通官方页面；
2. 确认页面展示字段和业务含义；
3. 观察页面加载时调用的官方接口；
4. 记录请求方法、URL、必要参数、Referer 和响应字段结构；
5. 将字段结构转写为人工构造、完全脱敏的测试样例；
6. 不保存真实响应和浏览器凭据；
7. 不点击缴费、申请发票、下载发票或其他写操作；
8. 遇到短信验证、风控、授权确认或 CAPTCHA 时停止，由用户处理。

已确认“剩余话费”页面可在当前 Chrome 登录会话正常展示余额、上月结转、本月存入和本月消费，因此应将此前“接口未暴露余额”的提示改为“当前 Skill 尚未接入独立余额接口”。

## 分批实施顺序

### 第一批：基础账户数据

- `balance`：剩余话费；
- `allowances`：余量查询；
- `bills`：我的账单。

第一批优先解决当前余额缺失，并建立通用业务客户端、统一返回结构和 CLI 框架。

### 第二批：历史财务记录

- `payments`：交费记录；
- `invoices`：已有电子发票查询；
- `rebates`：返费与赠款。

### 第三批：敏感或区域差异能力

- `usage-details`：详单查询；
- `contract-bills`：金融合约账单。

每批都必须独立测试、提交和发布，不要求等待全部能力完成。

## 异常处理

- 页面存在但接口返回空数据：返回空列表和实际查询范围，不伪造记录；
- 字段因省份或账户类型不同而缺失：返回 `partial` 和缺失项警告；
- 扫码会话过期：指出失效账户别名，引导重新扫码；
- 需要二次认证：返回专用错误，要求用户在联通官方页面完成；
- 接口结构变化：停止解析并返回“联通接口结构已变化”；
- 地区不支持：标记 `unsupported`，不影响其他命令；
- 查询过于频繁：复用账户级刷新保护；
- 单项接口失败：仅影响该命令，不破坏其他查询能力。

## 测试与验收

每项能力按测试驱动方式实现：

- 先用人工构造的脱敏字段结构编写解析失败测试；
- 覆盖正常、空数据、字段缺失、登录过期、二次认证和区域差异；
- 网络层验证方法、URL、Referer、必要参数和状态码处理；
- CLI 验证账户选择、月份、时间范围、JSON、中文摘要和错误码；
- 脱敏测试验证完整号码、发票号和凭据不会进入输出；
- 完整运行 pytest、Ruff、mypy、构建和 Agent Skill 校验。

验收标准：

- Chrome 页面可见的基础查询信息能由 CLI 以稳定 JSON 返回；
- Agent 不需要理解联通网页结构和私有字段；
- 所有命令支持中文账户别名和多账户选择；
- 所有能力保持只读，敏感信息不进入日志和 Git；
- 单项接口故障不会影响其他业务查询；
- 第一批完成后，“剩余话费”能返回与联通官方页面一致的金额语义。

## 本次范围

本设计覆盖八项联通网页只读查询能力及 Agent 触发文档。首个实施计划优先完成第一批能力，并为后两批建立稳定扩展接口。任何缴费、发票申请或下载、账户修改和合约办理均不在本次范围内。
