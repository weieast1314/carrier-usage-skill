# 中国联通网页明细查询与中文触发词设计

## 背景

当前中国联通扫码 Provider 已能通过网上营业厅会话查询余额、套餐名称、剩余流量和剩余语音，但首页接口只提供汇总值。联通“余量查询”页面还能展示流量包、语音包、短信、主副卡使用量和联通云盘空间，需要将这些只读能力纳入通用运营商 Skill。

## 目标

- 复用现有中国联通 APP 扫码生成的网页会话。
- 调用“余量查询”页面实际使用的网页接口，不要求查询时启动浏览器。
- 支持账户概览、流量、语音、短信、成员/副卡、云盘和套餐查询。
- 使用中文自然语言触发词选择最小查询范围。
- 保留中国移动、中国电信和中国广电 Provider 的扩展边界。
- 所有号码脱敏；不输出或持久化 Cookie、令牌和原始个人数据响应。

## 非目标

- 不办理充值、缴费、套餐变更、退订或云盘开通。
- 不查询通话详单、短信详单、上网记录或通信对象。
- 不绕过验证码、设备校验、风控或实名认证。
- 不把网页 DOM 抓取作为正式查询实现。
- 不承诺所有省份返回完全相同的资源分类。

## 已验证的页面能力

基于已登录的官方网上营业厅页面，已确认可见以下数据：

| 能力 | 可用字段 |
|---|---|
| 账户概览 | 余额、剩余流量、剩余语音、积分 |
| 套餐信息 | 套餐名称、查询时间 |
| 流量汇总 | 通用流量和其他流量的已用、剩余 |
| 流量明细 | 流量包名称、资源类型、共享属性、总量、已用、剩余 |
| 语音明细 | 语音包名称、共享属性、总量、已用、剩余 |
| 成员用量 | 主卡/副卡角色、脱敏号码、成员语音使用量；其他成员字段按接口实际返回 |
| 短信余量 | 已用条数、剩余条数 |
| 其他资源 | 联通云盘状态、会员等级、总空间、已用空间 |

## 方案选择

采用“复用扫码会话并直接调用网页接口”的方案。

浏览器仅用于接口调研、人工验证和上游变更诊断。正式 CLI 不依赖浏览器常驻。联通 App 接口暂不作为扫码 Provider 的默认路径，因为网页扫码会话不能直接满足 App 接口认证要求。

## 架构

### Provider 层

扩展 `ChinaUnicomWebProvider`：

1. 加载权限为 `0600` 的扫码会话。
2. 调用首页汇总接口完成认证验证和基础账户查询。
3. 按查询范围调用余量页面使用的明细接口。
4. 将联通字段转换为通用模型。
5. 单个非核心明细失败时返回部分结果和中文警告。

接口 URL、请求方法、请求头和字段映射集中放在联通网页 Provider 内，不进入通用服务层或 SKILL.md。

### 通用模型层

保留现有 `Allowance` 表示流量、语音和短信资源。新增：

- `LineRole`：`primary`、`secondary`、`member`、`unknown`。
- `LineUsage`：脱敏号码、角色和该成员的余量项目。
- 云盘等非通信资源使用独立的通用资源模型，不伪装成移动流量。
- `CarrierSnapshot` 增加可选成员和其他资源集合，旧 Provider 可返回空集合。

所有容量在 JSON 中统一使用 byte，语音使用 second，短信使用 count。联通原始分类保存在可选 `raw_type` 中。

### 查询范围

CLI 支持按范围查询，避免每次调用所有接口：

| 范围 | 数据 |
|---|---|
| `overview` | 余额、积分、套餐、用量汇总 |
| `data` | 流量汇总与流量包明细 |
| `voice` | 语音汇总与语音包明细 |
| `sms` | 短信汇总与短信包明细 |
| `members` | 主卡/副卡角色、脱敏号码及成员用量 |
| `resources` | 云盘等其他只读资源 |
| `all` | 上述全部能力 |

默认 `query` 使用 `overview`。用户明确询问明细时，Skill 选择对应范围。成员能力默认启用，但普通概览不展开成员信息。

## 中文触发词

Skill 元数据和正文覆盖下列意图与同义表达：

| 意图 | 示例触发词 | 查询范围 |
|---|---|---|
| 账户概览 | 查联通余额、查话费、查积分、查账户概览 | `overview` |
| 流量汇总 | 查流量、还剩多少流量、本月用了多少流量 | `data` |
| 流量明细 | 查流量明细、有哪些流量包、查通用流量、查其他流量 | `data` |
| 语音明细 | 查通话分钟、查语音余量、还剩多少分钟 | `voice` |
| 短信明细 | 查短信余量、用了多少短信 | `sms` |
| 成员用量 | 查成员流量、查副卡用量、哪张卡用了流量、查主副卡 | `members` |
| 云盘空间 | 查联通云盘、云盘还剩多少空间 | `resources` |
| 套餐信息 | 查当前套餐、套餐叫什么、套餐资费 | `overview` |
| 全部信息 | 查全部用量、查看完整余量 | `all` |

触发词用于 Skill 发现和查询范围选择，不在代码中维护脆弱的完整自然语言分类器。Agent 根据意图选择 CLI 参数。

## 输出规则

- 摘要格式默认中文。
- 普通概览只显示账户级数据，不自动列出成员。
- 明细输出按资源类别和流量包/语音包分组。
- 成员查询显示“主卡/副卡 + 脱敏号码”，不显示完整号码。
- 缺失字段显示“未提供”或省略，不根据总量和剩余量之外的数据猜测上游含义。
- JSON 保持稳定的通用字段和 `schema_version`。
- 不输出原始响应、请求头、Cookie 或令牌。

## 错误处理

- 登录失效：返回认证错误并引导重新扫码。
- 上游限流：返回剩余等待时间，不自动高频重试。
- 单个明细接口失败：保留其他成功结果，在 `warnings` 中说明缺失范围。
- 核心认证或首页汇总失败：查询整体失败，不返回可能属于过期会话的数据。
- 字段结构变化：停止猜测字段，返回上游结构变化错误。
- 某省不提供能力：返回 `unsupported` 或部分结果，不伪造零值。

## 安全与隐私

- 仅查询用户本人或明确授权的账户。
- 成员/副卡能力默认可用，但仅在明确意图下展开。
- 完整手机号在进入模型前即脱敏。
- 测试使用人工构造的匿名响应，不保存真实接口响应。
- 会话文件保持本机 `0600` 权限并继续受 Git 忽略规则保护。
- Provider 只允许向 `10010.com` 及其官方子域发送会话 Cookie。

## 测试策略

- 为每类网页响应编写匿名 fixture 和解析单元测试。
- 覆盖单位换算、缺失字段、无限资源、共享属性、主副卡和未知分类。
- 覆盖查询范围，验证未请求的接口不会被调用。
- 覆盖部分失败、认证失效、限流和上游结构变化。
- 覆盖中文摘要及 JSON 脱敏。
- 使用真实扫码会话执行一次只读人工验收，但不把结果写入仓库。
- 运行 pytest、Ruff、格式检查、mypy、Skill 校验和 Python 构建。

## 验收标准

1. “查流量明细”能返回各流量包的总量、已用和剩余。
2. “查语音余量”能返回语音汇总和各语音包。
3. “查短信余量”能返回短信已用和剩余。
4. “查副卡用量”能返回脱敏的主副卡角色和可用成员数据。
5. “查联通云盘”能返回会员状态、总空间和已用空间。
6. 普通概览不会自动展开成员信息。
7. 任意输出都不包含完整手机号、Cookie、令牌或原始响应。
8. 其他运营商 Provider 无需实现新能力也能继续满足通用协议。
